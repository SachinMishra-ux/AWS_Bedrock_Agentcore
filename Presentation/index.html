AWS BEDROCK OVERVIEW

Demystifying AWS Bedrock

Amazon Bedrock is a fully managed, serverless AWS service that provides developer access to high-performing foundation models (FMs) via a single, unified API.

Core Mission: Bedrock abstracts away the complexities of hosting and running massive machine learning models, allowing developers to focus on application logic and prompts.
🔌

Unified API

One unified client API connects to multiple model providers: Anthropic, Meta, Mistral, Cohere, and Amazon.

🛡️

Enterprise Security

Your data is encrypted, never exits the VPC, and is never used to train the base model providers.

⚡

Serverless Scale

Zero infrastructure management. Pay only for token ingress/egress or provisioned throughput.

Educator Note: Emphasize that Bedrock is the *foundation layer* in AWS for generative AI. It gives you the brains (models) and initial safety wrappers. Ask students: "Why is a unified API valuable when model capabilities change every month?"
AWS BEDROCK CAPABILITIES

Key Services Under Bedrock

Amazon Bedrock is not just model access; it is an ecosystem of features that wrap and customize foundation models.

01

Knowledge Bases

Out-of-the-box **Retrieval-Augmented Generation (RAG)**. Automatically syncs documents in S3, chunks/embeds them, and loads them into vector databases (OpenSearch Serverless, Pinecone, Aurora) for context-aware querying.

02

Guardrails

Apply custom safety parameters. Filters out toxic content, masks PII (Personally Identifiable Information) before model input or after output, and blocks prohibited topics using simple keyword or natural language rules.

03

Model Customization

Fine-tune model weights or run continued pre-training on proprietary datasets securely. You can also import custom weights directly via Custom Model Import.

04

Model Evaluation

Compare models side-by-side using automatic criteria (accuracy, toxicity) or human evaluation tasks to select the most cost-effective and capable foundation model for your workload.

Educator Note: Point out that Guardrails acts as a firewall *between* the user and the LLM, whereas Knowledge Bases is the automated data pipeline feeding the LLM.
THE SHIFT TO AGENTS

From Simple Prompts to Autonomous Agents

Standard LLMs are passive: they wait for a prompt, process it, and output text. In contrast, AI Agents are active loops that can plan, reason, invoke external tools, and remember context across sessions.

"The hardest part of building AI agents isn't writing the first prototype loop; it's secure deployment, scaling session memory, managing identity permissions, and evaluating behavior in production."
1

Local Framework Limitations

LangGraph, CrewAI, and AutoGen are excellent for prototyping, but lack native cloud scaling, secure sandbox execution, and centralized policy control.

2

Enterprise Needs

Organizations require secure session isolation, user authentication, auditing (observability), and strict authorization over what databases and tools an agent can call.

★

The Solution: AgentCore

A fully managed, framework-agnostic platform specifically built to deploy and scale production agents with enterprise compliance.

Educator Note: This is a crucial slide. It establishes *why* AWS AgentCore is necessary. It isn't replacing popular libraries like LangGraph; it's a cloud runtime and orchestration layer that secures and scales them.

AGENTCORE MODULES • BUILD & TOOLS

Harness & Built-In Tools

The starting point of building agentic logic within the AgentCore platform.

🛠️ Harness ↓

Harness is a **fully managed agent loop** execution environment. It abstracts infrastructure management and orchestrates the prompt-response cycles automatically.

  • Gives every agent session an isolated workspace with its own sandbox filesystem and virtual terminal.
  • Requires only defining model, system prompt, and tools list to get started.
📦 Built-in Tools ↓

Provides robust integrations of Amazon's managed operational tools directly into the agent context.

  • **Secure Browser**: Allows agents to search, browse, and extract content from websites in real-time.
  • **Code Interpreter**: Runs sandboxed Python environment to execute mathematical computations, compile charts, or process CSV files.
  • **Knowledge Bases & Search**: Native connections to AWS information repositories.
AgentCore CLI Demo
$ npm install -g @aws/agentcore
✓ Installed AgentCore CLI v1.2.0
$ agentcore init my-agent
Initializing new agent skeleton...
Created files:
- agent.json (config)
- prompt.txt (system instructions)
- index.js (custom logic)
$ agentcore deploy --harness
Deploying my-agent to AWS AgentCore Harness...
🚀 Harness active! Invoke Endpoint: https://agentcore.us-east-1.amazonaws.com/harness/arn:...
Educator Note: The code interpreter here runs in a secure sandbox, separate from the server. Harness automates the agent's logic flow, so the developer does not need to write `while true` loop handling.
AGENTCORE MODULES • CORE CONNECTIONS

Gateways & Secure Identity

Connecting agents to external APIs and managing permissions safely is critical in enterprise architectures.

🔌 Gateways

Gateways use open source protocols, specifically the **Model Context Protocol (MCP)**, to expose tools to agents. This enables seamless connection to schemas and integrations without custom server architecture.

  • Supports OpenAPI standard configurations.
  • Pre-built integrations automatically parse API parameters.
  • Requires zero infrastructure configuration to connect to third-party endpoints.

🔑 Identity (Inbound & Outbound)

Identity enables agents to securely manage access to resources by integrating with corporate identity providers (such as AWS IAM Identity Center or Auth0).

Inbound Identity

Enables caller authentication. Verifies that the client invoking the agent has permission to start the session.

↓
Outbound Identity

Enables downstream resource delegation. The agent securely requests tokens to call corporate databases or calendars under the user's delegated identity.

Educator Note: MCP (Model Context Protocol) is an industry-open standard backed by Anthropic and AWS. Highlight that Gateways make MCP a managed AWS infrastructure element.
AGENTCORE MODULES • CONTEXT & CONTROL

Memory & Policy Control

Giving agents memory makes them intelligent; putting guardrails and policy constraints makes them safe.

🧠 State and Memory Management

Memory enables agents to retain knowledge and learn continuously from every interaction, preventing context-blindness across sessions.

Short-Term Memory

Keeps track of conversation history within the current active session (e.g. current variables, task stack).

Long-Term Memory

Automatically extracts and archives facts, entities, and user preferences across multiple historical sessions to provide continuity.

🛡️ Policy (Cedar Auth)

Policy provides **deterministic control** over agent behavior. While LLMs are probabilistic, policy engines guarantee compliance with business rules.

AWS Cedar Integration

Rules can be authored in natural language or using **Cedar**—AWS's open-source policy language—to set fine-grained permissions.

permit (
    principal == User::"Alice",
    action == Action::"ReadAccountBalance",
    resource == Account::"12345"
) when {
    resource.region == "US"
};
Educator Note: Note that Memory is automatic. Developers do not need to write database retrieval scripts or vector stores manually for user preferences. Policy guarantees that even if the LLM decides to trigger an action, AWS blocks it at the Gateway if it violates Cedar policy.
AGENTCORE MODULES • DEPLOYMENT & SHARING

Registry & Runtime

Discovering agent assets across teams and running them in isolated serverless compute instances.

📂 Registry (Preview)

A centralized hub to publish, version, share, and reuse agentic assets across an entire enterprise organization.

  • **Asset Discovery**: Register existing agents, MCP servers, standalone tools, and specific skill bundles.
  • **Version Control**: Lock specific agent versions for production workloads while testing new iterations in sandbox.
  • **Collaboration**: Promotes organizational reusability and avoids redundant tool implementation.

🚀 Runtime for Agents and Tools

Runtime is the execution engine of AgentCore, providing a secure, serverless, and purpose-built environment to scale agent code.

⚡ Fast Cold Starts

Optimized for instantaneous invocation, preventing latency spikes during customer chats.

🔒 True Session Isolation

Each user session runs in an isolated compute boundary with local sandboxing.

🤖 Agnostic Scaling

Supports any model and any code library (Python, JS, Go). Scale agents up and down automatically.

Educator Note: Runtime behaves like a container service tailored for AI agent loops. It handles long-running multi-modal inputs without timeout limits commonly faced by standard Serverless functions.
AGENTCORE MODULES • VALUE & ASSESSMENT

Payments, Observability & Evaluations

Handling paid content access and assessing model behavior with metrics and trace execution logs.

💳 Payments

Enables AI agents to autonomously execute micro-transaction payments for paid APIs, custom tools, or proprietary knowledge content.

  • Credentials and wallets are securely managed under **AgentCore Identity**.
  • Enables pay-per-call capabilities, facilitating agent-to-agent economics.

📊 Observability & Evaluations

Ensures engineers can monitor and evaluate production agent behavior over time.

🔍 Observability

Collects detailed trace logs. Step-by-step reasoning paths show what tools the agent called, what prompts were generated, and what outputs were returned.

📈 Evaluations

Supports batch evaluations, online evaluation configs, and custom metrics to test changes to prompt structures or foundation models before deployment.

Educator Note: The payment module is a major advancement, allowing agents to spend small budgets on their own API requests. The evaluation module helps engineers avoid regressions when changing prompt templates.
COMPARATIVE ANALYSIS

Amazon Bedrock Agents vs. AgentCore

Students often confuse these two offerings. Here is the distinction between Bedrock Agents (AWS's default agent builder) and Bedrock AgentCore (the managed platform runtime).

Dimension Amazon Bedrock Agents (Classic) Amazon Bedrock AgentCore
Primary Focus Simple, low-code AWS-native agent builder. Managed platform/runtime to deploy and scale *any* agent.
Framework Support Locked to Amazon's proprietary orchestration loop. **Framework Agnostic** (LangGraph, CrewAI, AutoGen, custom code).
Model Agnosticism Optimized for Bedrock-native models (e.g. Claude, Titan). **Model Agnostic** (Allows bringing outside models, custom imported FMs).
Extensibility Requires AWS Lambda action groups. Supports **Model Context Protocol (MCP)**, sandboxed execution.
Session Memory Managed session attributes (ephemeral). **Automated Short & Long term memory** across multiple sessions.
Security Control AWS IAM roles per agent. Granular **Cedar Policy authorization** + Inbound/Outbound identity.
Educator Note: Explain this as: Bedrock Agents (Classic) is like an Apple ecosystem—highly integrated, fast to build, but closed. AgentCore is like a managed Kubernetes container cluster specifically tuned for AI agents—it hosts and manages whatever agent code framework you choose.
